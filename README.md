# 해설사 근무편성표

종이로 돌려보던 월별 근무편성표를 휴대폰에서 보고, 근무자끼리 직접 바꾸고,
바뀐 내용이 모두에게 즉시 보이도록 만든 앱입니다.

- **웹페이지이자 앱입니다.** 주소만 알면 컴퓨터에서 열리고, 휴대폰에서는 홈 화면에 추가하면 아이콘이 생겨 앱처럼 열립니다. (설치·스토어 검색 필요 없음)
- **큰 글씨, 큰 버튼.** 앱 안에서 글자 크기를 3단계로 키울 수 있습니다.
- **근무 교대는 3단계.** 날짜 고르기 → 상대 고르기 → "이렇게 바뀝니다" 확인. 바꾼 직후 같은 화면에서 바로 되돌릴 수 있습니다.
- **모든 변경이 기록됩니다.** 누가·언제·무엇을 바꿨는지 남고, 잘못된 변경은 되돌리기 한 번으로 원상복구됩니다.
- **근무표 등록은 두 가지 방법.** 엑셀 업로드 / 화면에서 직접 입력.

## 1. 계정을 누구 것으로 만들 것인가

> 요청하신 대로 **소유는 다른 분 계정, 나는 협업자**로 구성하는 방법입니다.

무료 플랜에서는 배포 서비스(Vercel·Netlify)에 팀원을 추가할 수 없습니다.
그래서 **협업은 GitHub에서 하고, 소유는 상대방 계정에 두는** 방식이 가장 깔끔하고 돈이 들지 않습니다.

| 서비스 | 계정 주인 | 나의 위치 | 하는 일 |
|---|---|---|---|
| **GitHub** | 상대방 | Collaborator (무료) | 코드를 여기서 같이 고칩니다 |
| **Vercel** 또는 **Netlify** | 상대방 | (필요 없음) | GitHub에 올린 코드를 자동으로 웹에 띄웁니다 |
| **Supabase** | 상대방 | 조직 멤버로 초대받음 (무료) | 근무표 데이터가 저장되는 곳 |

**설정 순서**

1. 상대방이 GitHub에서 저장소를 새로 만들고, `Settings → Collaborators → Add people` 에서 나를 추가합니다.
2. 이 폴더의 내용을 그 저장소에 올립니다.
3. 상대방이 자기 계정으로 Vercel(또는 Netlify)에 로그인해서 그 GitHub 저장소를 연결합니다.
   → 이제부터 내가 코드를 GitHub에 올릴 때마다 **상대방 소유의 사이트가 자동으로 갱신**됩니다.
4. 상대방이 자기 계정으로 Supabase 프로젝트를 만들고, `Organization → Team → Invite` 로 나를 초대합니다.

이렇게 하면 서비스 소유권은 전부 상대방에게 있고, 나는 코드와 데이터베이스를 자유롭게 손볼 수 있습니다.

## 2. 설치하기 (한 번만 하면 됩니다)

### 2-1. Supabase 프로젝트 만들기

1. <https://supabase.com> 에서 새 프로젝트를 만듭니다. (지역은 **Northeast Asia (Seoul)** 추천)
2. `SQL Editor` 를 열고 **`supabase/schema.sql`** 의 내용을 전부 붙여넣고 실행합니다.
3. 이어서 **`supabase/seed.sql`** 을 붙여넣고 실행합니다.
   - 2026년 7월 근무표에 있던 조·근무지·해설사 25명이 등록됩니다.
   - 명단은 나중에 앱의 `[더보기] → [해설사 명단 관리]` 에서 얼마든지 고칠 수 있습니다.

### 2-2. 첫 관리자 계정 만들기

1. Supabase 대시보드 → `Authentication` → `Users` → `Add user` → `Create new user`
   - **Email**: `admin@guide.local`
   - **Password**: `0000jeju-guide-2026` ← *PIN 4자리 + 아래 `VITE_PIN_PEPPER` 값을 붙여쓴 것*
   - **Auto Confirm User** 체크
2. `SQL Editor` 에서 `seed.sql` 맨 아래의 `update public.members ...` 한 줄을 실행합니다.

이제 앱에서 **관리자 → PIN 0000** 으로 로그인할 수 있습니다.

### 2-3. 환경 변수 넣기

`.env.example` 을 복사해 `.env` 파일을 만들고 값을 채웁니다.
(Supabase 대시보드 → `Project Settings` → `API` 에서 복사)

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
VITE_LOGIN_EMAIL_DOMAIN=guide.local
VITE_PIN_PEPPER=jeju-guide-2026
```

> **`VITE_PIN_PEPPER` 는 한 번 정하면 절대 바꾸지 마세요.**
> 4자리 PIN을 Supabase의 최소 비밀번호 길이에 맞추려고 뒤에 붙이는 고정 문자열입니다.
> 이 값을 바꾸면 모든 사람의 PIN이 한꺼번에 무효가 됩니다.

Vercel/Netlify에 배포할 때도 같은 값을 **환경 변수(Environment Variables)** 로 넣어줘야 합니다.

### 2-4. Edge Function 올리기

계정 관리는 브라우저에서 다룰 수 없는 열쇠가 필요해서 서버 쪽 함수로 되어 있습니다.

**방법 A — 대시보드에서 붙여넣기 (쉬움, 권장)**

1. Supabase 대시보드 → `Edge Functions` → `Deploy a new function` → `Via Editor`
2. 이름을 `manage-user` 로 하고, `supabase/functions/manage-user/index.ts` 내용을 통째로 붙여넣고 배포합니다.
3. `Edge Functions` → `Secrets` 에서 아래 값을 추가합니다.
   - `LOGIN_EMAIL_DOMAIN` = `guide.local`
   - `PIN_PEPPER` = `jeju-guide-2026`

**방법 B — 명령어로 배포**

Supabase CLI는 전역 설치(`npm install -g`)가 지원되지 않으므로 프로젝트 안에 설치해서 `npx` 로 씁니다.

```bash
npm install supabase --save-dev
npx supabase login
npx supabase link --project-ref <프로젝트 ref>

npx supabase secrets set LOGIN_EMAIL_DOMAIN=guide.local PIN_PEPPER=jeju-guide-2026
npx supabase functions deploy manage-user
```

### 2-5. 로컬에서 확인 / 배포

```bash
npm install
npm run dev      # 내 컴퓨터에서 확인
npm run build    # 배포용 파일 만들기 (dist 폴더)
```

Vercel/Netlify에 GitHub 저장소를 연결하면 `npm run build` 는 자동으로 실행됩니다.

- 안드로이드: 크롬 오른쪽 위 **점 세 개(⋮)** → **홈 화면에 추가**

## 4. 관리자가 하는 일

| 하고 싶은 것 | 어디서 |
|---|---|
| 이번 달 근무표 올리기 | `[더보기] → [근무표 등록하기]` |
| 한두 칸만 고치기 | `[전체 근무표]` 에서 칸을 누르면 담당자/휴무를 바꿀 수 있음 |
| 새 해설사 추가 | `[더보기] → [해설사 명단 관리] → [해설사 추가하기]` |
| PIN을 잊은 사람 | 같은 화면에서 `[PIN 초기화]` |
| 그만둔 사람 | 같은 화면에서 `[사용 중지]` (기록은 남고 로그인만 막힘) |
| 잘못된 변경 되돌리기 | `[변경 이력]` 에서 `[되돌리기]` |

### 근무표 등록 두 가지 방법

1. **엑셀** — `[빈 양식 내려받기]` 로 받은 파일에 이름을 채워 다시 올립니다. 가장 정확합니다.
   첫 줄에 `일자`와 근무지 이름이 있어야 하고, 쉬는 날은 `휴무` 라고 적습니다.
   올린 결과는 **반드시 검토 화면**을 거칩니다.
   - 노란 칸 = 비슷한 이름으로 짐작한 곳 (확인 필요)
   - 빨간 칸 = 명단에 없는 이름 (반드시 골라야 저장됨)
2. **직접 입력** — 빈 표를 만들어 칸마다 사람을 고릅니다.

## 5. 변경과 되돌리기가 어떻게 동작하나

- 근무자는 **본인이 포함된 교대만** 할 수 있습니다. (남의 근무끼리 바꾸는 건 관리자만)
- 교대는 **두 칸이 한 번에** 바뀝니다. 데이터베이스 한 트랜잭션 안에서 처리하므로 "한쪽만 바뀌는" 사고가 나지 않습니다.
- 교대 한 건은 이력에 두 줄로 남되 하나로 묶여 있어서, **되돌리면 두 칸이 함께** 원래대로 돌아갑니다.
- 되돌릴 수 있는 사람: **그 변경을 한 본인**, 그리고 **관리자**.
- 되돌린 기록도 이력에 남습니다. (지워지지 않습니다)
- 종이 근무표에서 녹색으로 표시하던 "변경된 칸"은 앱에서도 **초록 글씨**로 표시됩니다.

## 7. 알아두실 점

- **PIN은 숫자 4자리**입니다. 어르신들이 쓰기 쉬운 대신 은행 수준의 보안은 아닙니다.
  근무표라는 성격상 적절하다고 보고 정한 것이며, 더 강하게 하려면 6자리로 늘릴 수 있습니다.
- **근무 교대는 같은 달 안에서만** 가능합니다. 화면에 불러온 달의 근무만 후보로 보여줍니다.
- 알림은 앱을 열었을 때 화면 위쪽에 표시됩니다. 휴대폰 푸시 알림(앱을 닫아둔 상태에서 울리는 알림)은 아직 넣지 않았습니다. 필요하시면 추가할 수 있습니다.
