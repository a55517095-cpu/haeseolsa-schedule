# 해설사 근무표 앱 — 설치 순서

시작 전 메모해 둘 값 2가지 (나중에 바꾸면 전원 로그인이 막힙니다)

| 항목 | 값 | 설명 |
| --- | --- | --- |
| 로그인용 가짜 도메인 | `guide.local` | 실제 메일을 보내지 않는 내부 식별용. 그대로 써도 됨 |
| PIN 뒤에 붙는 고정 문자열 | `jeju-guide-2026` | PIN 4자리를 비밀번호 최소 길이에 맞추려고 붙임 |

아래 설명은 위 값을 그대로 쓴다고 가정합니다.

## 1단계 · 계정 만들기 — 상대방이 (20분)

상대방과 같이 앉아서 하는 게 빠릅니다. 상대방 이메일로 만듭니다.

- [ ] GitHub 가입 — https://github.com/signup
- [ ] Supabase 가입 — https://supabase.com → `Sign in with GitHub`
- [ ] Vercel 가입 — https://vercel.com → `Continue with GitHub`
- [ ] (사진 인식 쓸 때만) Anthropic Console — https://console.anthropic.com → 결제수단 등록 → `API Keys` 에서 키 발급

> 사진 인식 없이 엑셀 + 직접 입력만 쓸 거면 마지막 항목은 건너뜁니다. 그러면 전부 무료로 운영됩니다.

## 2단계 · Supabase 프로젝트와 데이터베이스 — 상대방 계정으로 (15분)

- [ ] Supabase 대시보드 → `New project`
- [ ] Name: `haeseolsa-schedule`
- [ ] Database Password: 아무거나 정하고 **어딘가에 저장** (직접 쓸 일은 없음)

## 3단계 · 첫 관리자 계정 — 상대방 계정으로 (5분)

> 2단계를 마친 뒤에 해야 합니다. 순서가 바뀌면 연결이 안 됩니다.

- [ ] 왼쪽 `Authentication` → `Users` → `Add user` → `Create new user`
- [ ] Email: `admin@guide.local`
- [ ] Password: `0000jeju-guide-2026`  ← PIN `0000` + 고정 문자열을 **띄어쓰기 없이 붙여쓴 것**
- [ ] **Auto Confirm User 체크** (필수)
- [ ] `Create user`
- [ ] `SQL Editor` → `New query` → 아래 한 줄을 붙여넣고 `Run`

```sql
update public.members
   set auth_user_id = (select id from auth.users where email = 'admin@guide.local')
 where login_code = 'admin';
```

- [ ] 결과가 **"Success. 1 row"** 인지 확인 (`0 rows` 면 이메일 오타)

## 4단계 · 접속 열쇠 받아서 내 컴퓨터에서 테스트 — 내가 (10분)

여기가 첫 번째 확인 지점입니다. 배포하기 전에 로그인이 되는지 먼저 봅니다.

- [ ] Supabase → `Project Settings`(톱니바퀴) → `API`
- [ ] **Project URL** 복사
- [ ] **anon / public key** 복사 (화면에 따라 `Publishable key` 로 표시되기도 함)
- [ ] 프로젝트 폴더에 `.env` 파일을 새로 만들고 아래 4줄 입력

```
VITE_SUPABASE_URL=https://여기에붙여넣기.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...여기에붙여넣기
VITE_LOGIN_EMAIL_DOMAIN=guide.local
VITE_PIN_PEPPER=jeju-guide-2026
```

- [ ] 터미널에서 `npm run dev` 실행
- [ ] 브라우저에서 `http://localhost:5173` 열기
- [ ] 조 선택 화면 → `2조` 아래 "그 외" 에 `관리자` 가 보이는지 확인
- [ ] `관리자` → PIN `0000` → **로그인 성공 확인**

문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| PIN이 맞지 않습니다 | 3단계 비밀번호를 `0000jeju-guide-2026` 으로 정확히 넣었는지 |
| 화면이 안 뜸 | `.env` 값에 따옴표나 앞뒤 공백이 섞였는지 |

## 5단계 · Edge Function 2개 올리기 — 상대방 계정으로 (15분)

해설사 계정 생성과 사진 인식은 서버에서만 다룰 수 있는 열쇠가 필요합니다.

- [ ] Supabase → `Edge Functions` → `Deploy a new function` → `Via Editor`
- [ ] 이름 `manage-user` → `supabase/functions/manage-user/index.ts` 내용을 통째로 붙여넣고 `Deploy`
- [ ] (사진 인식 쓸 때만) 이름 `ocr-schedule` → `supabase/functions/ocr-schedule/index.ts` 붙여넣고 `Deploy`
- [ ] `Edge Functions` → `Secrets` 에서 아래 값 추가

| 이름 | 값 |
| --- | --- |
| `LOGIN_EMAIL_DOMAIN` | `guide.local` |
| `PIN_PEPPER` | `jeju-guide-2026` |
| `ANTHROPIC_API_KEY` | `sk-ant-...` (사진 인식 쓸 때만) |

- [ ] 앞의 두 값이 4단계 `.env` 와 **글자 하나까지 같은지** 확인

## 6단계 · GitHub에 올리고 나를 협업자로 (15분)

상대방이 먼저

- [ ] GitHub → `New repository` → 이름 `haeseolsa-schedule` → **Private** → `Create`
- [ ] `Settings` → `Collaborators` → `Add people` → 내 GitHub 아이디 추가

나는 초대 메일 수락 후, 프로젝트 폴더에서

- [ ] 아래 명령을 순서대로 실행

```bash
git init
git add .
git commit -m "해설사 근무편성표 앱"
git branch -M main
git remote add origin https://github.com/상대방아이디/haeseolsa-schedule.git
git push -u origin main
```

> `.env` 는 자동으로 제외됩니다. 열쇠가 GitHub에 올라가지 않습니다.

## 9단계 · 해설사 25명 로그인 계정 만들기 — 관리자로 (20분)

- [ ] 앱에서 `더보기` → `해설사 명단 관리`
- [ ] "로그인 계정이 없는 사람이 25명 있습니다" 안내 확인
- [ ] 이름마다 `계정 만들기` 를 눌러 PIN 지정

PIN 정하는 방법 — 둘 중 하나로 통일

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 전원 `0000` | 문자 한 통으로 전체 안내 가능 | 각자 바꾸도록 안내 필요 |
| 휴대폰 번호 뒤 4자리 | 본인 것이라 덜 헷갈림 | 개인별로 따로 안내해야 함 |

## 10단계 · 근무표 등록 — 관리자로 (15분)

- [ ] `더보기` → `근무표 등록하기`
- [ ] 위에서 연/월과 조를 맞추기 (**1조와 2조는 따로 등록 — 총 2번**)
- [ ] 입력 방법 고르기

| 방법 | 설명 |
| --- | --- |
| 엑셀 (권장) | `빈 양식 내려받기` → 이름 채워서 다시 올리기. 가장 정확 |
| 사진 | 종이 근무표를 찍어 올리면 AI가 읽음 |
| 직접 입력 | 빈 표에서 칸마다 사람 고르기 |

- [ ] 검토 화면에서 **노란 칸**(비슷한 이름으로 짐작) 확인
- [ ] **빨간 칸**(명단에 없는 이름) 전부 고르기 — 고르기 전엔 저장 안 됨
- [ ] 안내 문구 입력 (예: `7월 8일(수)은 특별탐방(사전예약)입니다`)
- [ ] `이대로 등록하기`

## 걸리는 시간 정리

| 언제 | 누가 | 시간 |
| --- | --- | --- |
| 1~3단계 | 상대방과 함께 | 40분 |
| 4~7단계 | 나 (상대방 로그인 필요) | 50분 |
| 8~10단계 | 나 | 40분 |

하루에 다 못 하면 **4단계(내 컴퓨터에서 로그인 성공)까지만** 해두면 됩니다. 거기까지 되면 나머지는 순서대로 따라가기만 하면 됩니다.

## 운영 중에 자주 쓰는 것

| 하고 싶은 것 | 어디서 |
| --- | --- |
| 이번 달 근무표 올리기 | `더보기` → `근무표 등록하기` |
| 한두 칸만 고치기 | `전체 근무표` 에서 칸을 누르기 |
| 새 해설사 추가 | `더보기` → `해설사 명단 관리` → `해설사 추가하기` |
| PIN을 잊은 사람 | 같은 화면에서 `PIN 초기화` |
| 그만둔 사람 | 같은 화면에서 `사용 중지` (기록은 남고 로그인만 막힘) |
| 잘못된 변경 되돌리기 | `변경 이력` 에서 `되돌리기` |
